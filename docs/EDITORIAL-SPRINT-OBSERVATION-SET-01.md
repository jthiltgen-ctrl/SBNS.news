## Canonical production path after review

Manual URL, submission-ready Watchdesk candidate, and (only after separately completed activation) allowlisted ordinary email create the existing Newsroom intake and its analysis job. A low-readiness Watchdesk discovery or broad search hit remains a lead, not an analyzed intake; an editor may still explicitly select **Analyze selected discovery**. The queue retrieves the submitted document, attempts at most two linked official records, and stores versioned analysis, claim/source identities and semantic relationships, and audit events in one Story File. The UI derives the evidence ledger, Editorial Frame, Draft 0 or withheld reason, and explicit human-review needs. A completed review-ready analysis may queue optional Echo research only when evidence-backed eligibility and 1–3 concise terms are present; Echo failure cannot erase or block the story analysis.

The analyzer must keep the observed condition distinct from institutional failure and specific-harm causation. Source expansion failure is nonfatal and visible; it does not upgrade any claim. A model-generated body paragraph is displayed only through valid, verified/qualified claim references with usable source relationships; contradictory/unresolved material is withheld or explicitly qualified. No generated text changes the human draft, decision, or publication records.

## Controlled Story Queue activation gate

Activation is not a code-merge side effect. After approved code deployment, the publisher must choose exact editor-controlled sender addresses and verify the existing deny-by-default policy. Set `STORYQUEUE_INGEST_TOKEN` and `STORYQUEUE_ALLOWED_SENDERS` securely on `sbns-admin`; verify protected Story Queue status. Then install the existing GreenGeeks relay outside the public web root with an owner-protected configuration containing the same token, and configure the `storyqueue@shockedbutnotsurprised.news` cPanel pipe without changing MX or disrupting mailbox retention. Only after this should one-URL, duplicate, multi-URL, notes, and attachment-exclusion tests be sent and their single intake/analysis/audit outcomes checked. Do not treat ordinary email as Secure Source. See [Story Queue email intake](STORYQUEUE-EMAIL-INTAKE.md) for limits and stop conditions.

## Echo release boundary

The bounded runtime bridge now turns source-supported LOC/optional Smithsonian metadata into `echo-candidate-v1` input, adds claim-linked contemporary evidence, a separate model-assisted Analogy Truth Test, conservative metadata/link-only rights review, and the existing deterministic gates. Search hits alone cannot become editor-ready. Unclear or indicated cultural protocols are not auto-cleared; they can cause a successful no-echo result. The Story File displays the packet and candidate limitations and records exact-assessment human FEATURE/HOLD/REJECT decisions. FEATURE is not story approval or publication. A failed packet can be retried only before its candidate package is bound; after that, a fresh live search is held for forward repair rather than risk a PR B `RETRY_INPUT_MISMATCH`.

The optional public `WE WERE WARNED` section is prepared only through the existing human-approved publication package. Its exact current FEATURE decision, pinned assessment, ready packet, and primary intake are checked with a SELECT-only D1 read before generating public-safe text/metadata/source links. No FEATURE means no component or placeholder. `NO CULTURAL ECHO WARRANTED` is a valid successful outcome. Controlled production Echo acceptance is a separate release step, not performed by this draft.

## Deployment and cost consequences

No migration is added; schema remains v6. A future merge would trigger the watched admin/public workflows and the new scoped analysis workflow. The analysis workflow validates, dry-runs, deploys with `SBNS_ANALYSIS_BUILD_SHA`, then reads back the active version and Queue consumers; it never applies migrations. **PRE-MERGE EXTERNAL PREREQUISITE — CLOUDFLARE TOKEN MUST AUTHORIZE sbns-analysis DEPLOYMENT**, including required version/consumer readback. The last documented staging token scope did not establish this. Search and bounded primary/Echo retrieval use existing public endpoints and Worker/AI bindings: new fixed recurring service cost is $0, but use-based retrieval/model charges may vary. This draft configures no Cloudflare permission, mail host, DNS, or production secret.
