## Canonical production path after review

Manual URL, approved Watchdesk intake, and (only after separately completed activation) allowlisted ordinary email all create the existing Newsroom intake. Manual URLs and allowlisted email queue analysis on intake. A Watchdesk discovery remains a lead until an editor explicitly selects **Analyze selected discovery** in its existing Story File; this reuses the ordinary analysis endpoint and queue. The analysis queue retrieves the submitted document, attempts at most two linked official records, runs the source-identified analyzer, and stores its analysis, sources, claims, claim/source links, and audit events in the same Story File. The UI derives the ledger, Editorial Frame, Draft 0 or withheld reason, and explicit human-review needs. Search results enter this path only after a human chooses a URL; they never create an intake automatically. Echo is **not** connected by this draft.

The analyzer must keep the observed condition distinct from institutional failure and specific-harm causation. Source expansion failure is nonfatal and visible; it does not upgrade any claim. A model-generated body paragraph is displayed only with valid, verified/qualified claim references and their cited sources. No generated text changes the human draft, decision, or publication records.

## Controlled Story Queue activation gate

Activation is not a code-merge side effect. After approved code deployment, the publisher must choose exact editor-controlled sender addresses and verify the existing deny-by-default policy. Set `STORYQUEUE_INGEST_TOKEN` and `STORYQUEUE_ALLOWED_SENDERS` securely on `sbns-admin`; verify protected Story Queue status. Then install the existing GreenGeeks relay outside the public web root with an owner-protected configuration containing the same token, and configure the `storyqueue@shockedbutnotsurprised.news` cPanel pipe without changing MX or disrupting mailbox retention. Only after this should one-URL, duplicate, multi-URL, notes, and attachment-exclusion tests be sent and their single intake/analysis/audit outcomes checked. Do not treat ordinary email as Secure Source. See [Story Queue email intake](STORYQUEUE-EMAIL-INTAKE.md) for limits and stop conditions.

## Echo hold and later release design

The existing Echo adapters yield bounded catalog records and verified historical-context metadata, while `echo-candidate-v1` deliberately requires an analogy Truth Test, contemporary-evidence references, rights/use assessment, protocol gate, and prior-use input. A safe runtime bridge must validate and audit those inputs before calling the existing deterministic orchestration. The present draft does not have that bridge, a human Echo decision UI, or an exact approved-candidate-to-published-story relationship. A public `WE WERE WARNED` card must therefore remain absent. Rendering an unreviewed search hit would cross the human authority and rights boundary.

This hold is not a claim that Echo has no editorial value. It is a release gate: demonstrate an eligible Story File → bounded verified candidate/no-echo result → exact FEATURE/HOLD/REJECT → separate approved-publication linkage with synthetic tests before activation. `NO CULTURAL ECHO WARRANTED` must remain a successful outcome. Do not create an Echo job in production to compensate for the missing path.

## Deployment and cost consequences

No migration is added; the schema remains v6. A future merge of this draft would trigger the watched admin and public deployment workflows because `src/**`, `public/admin-persistent/**`, and `package.json` changed. **It would not deploy `sbns-analysis`**: no analysis deployment workflow exists, and the last documented CI token scope did not authorize that Worker. Before merging this branch, production release planning must separately authorize and prove a bounded analysis-Worker deployment path and verification; otherwise new analyzer code and the model setting remain inactive while the admin UI changes go live. The model setting must be tested against protected production diagnostics before the historic analysis defect can be called resolved. Search and primary-record expansion use existing public endpoints and Worker/AI bindings: new fixed recurring service cost is $0, but use-based retrieval/model charges and rate limits may vary. This draft does not configure any Cloudflare, mail-host, DNS, or production secret state.
